### Key learnings
- `nemoclaw elliot connect` is **interactive only** — no exec/non-interactive subcommand exists
- `docker exec` reaches container level but NOT the k3s sandbox filesystem (openclaw binary not findable)
- `openclaw-gateway` process IS visible via `docker exec ... ps aux` even though binary is not accessible
- launchd PATH does not include `/opt/homebrew/bin` or `~/.local/bin` — always use full paths in plists
- Use wrapper script pattern for launchd jobs that need complex PATH or environment
- `nemoclaw elliot status` runs non-interactively and returns parseable output (Phase: Ready)
- `launchctl unload` can fail with I/O error if job is in bad state; use `launchctl bootout gui/$(id -u)` to force-remove
