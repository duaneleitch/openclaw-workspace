# Shared Obsidian Vault Operating Rules

## Purpose

This vault is the shared second brain for Duane and authorized agents. It preserves original evidence, publishes reusable knowledge, and supports reliable retrieval.

## Read Order

1. Read this file.
2. Read [[00_System/Context_Rules]].
3. Use [[00_System/Router]] to select only the relevant knowledge and operational files.
4. Follow source links when an answer needs evidence or deeper detail.

## Non-Negotiable Rules

- Never delete a Markdown file.
- Never alter raw source assets or transcripts after capture.
- Never create an action item unless Duane explicitly asks.
- Cite the vault note or raw source used for material internal claims.
- Treat drafts, generated outputs, mirrors, and archives as lower authority than published knowledge.
- Do not reorganize existing content outside an approved, manifest-backed migration batch.

## Ownership

- **00_Inbox:** humans and authorized agents may add intake records.
- **10_Raw:** capture workflows create new source folders only. Existing raw files are immutable.
- **20_Knowledge:** the governed digest workflow or an authorized reviewer publishes reusable knowledge notes.
- **30_Operations:** designated operational workflows maintain projects, decisions, and digests.
- **05_Action_Items:** only the Action Register workflow maintains Duane's canonical actions.
- **90_Archive:** migration and archival workflows only.

## Retrieval Priority

1. Published wiki and current operational records.
2. Source notes and raw transcripts when evidence is needed.
3. Existing domain folders routed by [[00_System/Router]].
4. Archive only when historical context is explicitly requested.
